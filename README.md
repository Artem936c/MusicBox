# MusicBox

**Telegram-бот + Mini App, который превращает приватный Telegram-канал в облачное
хранилище музыки.** Загружаете аудио боту — файл уезжает в ваш приватный канал,
а в базе остаётся карточка трека: исполнитель, альбом, длительность, папка,
счётчик прослушиваний. Слушать можно прямо в Telegram — в чате с ботом или
в веб-приложении (Mini App) с плеером, плейлистами и статистикой.

Хранилище бесплатное и безлимитное: файлы физически лежат в Telegram,
на вашем сервере — только SQLite-база размером в единицы мегабайт.

Версия 2 добавила вложенные папки, нескольких исполнителей у трека, раздел
«Другое» для документов, видео, кружочков и голосовых, заметки со списками,
рекомендации исполнителей и систему миграций базы. Обновляетесь с версии 1 —
начните с раздела [5](#5-обновление-с-версии-1-на-версию-2).

## 1. Что умеет MusicBox

### Хранилище и загрузка

- **Приватный канал как облако.** Каждый присланный боту файл копируется
  в приватный канал; в базе сохраняется `file_id` копии из канала — ссылка,
  по которой файл отдаётся бесконечно долго и не занимает места на сервере.
- **Загрузка любым способом:** отправить боту аудиофайл, отправить документ
  с аудио-mime (`audio/mpeg`, `audio/flac` и т.п.), **переслать** трек из
  публичного канала или чата.
- **Не только музыка.** Бот принимает документы, видео, видеосообщения
  («кружочки») и голосовые — они сохраняются в тот же канал и попадают
  в раздел «Другое». Что куда относится — раздел
  [19](#19-разделы-треки-и-другое).
- **Разбор метаданных:** название, исполнитель, альбом, длительность берутся
  из данных Telegram, ID3-тегов (если установлен `mutagen`) или из имени файла
  формата `Исполнитель - Название.mp3`. Названия чистятся от мусора вроде
  `[official video]`, подчёркиваний и расширений.
- **Автосортировка по исполнителю.** При включённой настройке трек сразу
  попадает в папку с именем исполнителя (папка создаётся при необходимости),
  при выключенной — бот спрашивает: «Сохранить в «X»» / «Создать папку «X»» /
  «Другая папка» / «Без папки». Похожие названия папок сопоставляются нечётко
  («Би-2» и «Би 2» — одна папка).
- **Защита от дублей:** повторная загрузка того же файла не создаёт вторую
  запись (уникальность по `file_unique_id`).

### Библиотека

- **Вложенные папки** — папка внутри папки до 16 уровней
  (`MAX_FOLDER_DEPTH`): дерево с раскрытием узлов, хлебные крошки, перенос
  папки вместе с содержимым, подсчёт треков «своих» и «с подпапками».
  Циклы (папка внутри самой себя) запрещены на уровне репозитория.
  Папки живут в двух разделах: `music` (музыка) и `other` («Другое»).
- **Несколько исполнителей у трека** — таблица `track_artists`, основной
  исполнитель остаётся в `tracks.artist_id`. Фильтр в поиске работает
  **на пересечение**: выбрали двух исполнителей — получите только те треки,
  где есть оба.
- **Исполнители** — автоматический список с отметкой «✅ прослушано»
  (ставится сама при первом воспроизведении) и ручным переключением,
  количеством треков, суммой прослушиваний (`artists.total_plays`),
  привязкой к папке. Исполнителя можно создать вручную (`/create_artist`)
  и переименовать (`/edit_artist`; при совпадении имён записи сливаются).
- **Альбомы (группы)** — автоматически из тегов, с числом треков и годом.
- **Избранное** — ⭐ одним нажатием из бота и из Mini App, с поиском внутри.
- **Плейлисты** — создание, описание, добавление/удаление треков,
  **drag-and-drop** порядок в Mini App, кнопки ⬆️/⬇️ в боте,
  «▶️ Проиграть плейлист» — бот присылает треки по очереди.
- **Заметки со списками** — заголовок и пункты с чекбоксами, произвольный
  порядок пунктов (`/notes` и страница `/notes` в Mini App). Таблицы `notes`
  и `note_items`.

### Поиск

- **Нечёткий поиск** по трекам, альбомам, исполнителям и папкам:
  устойчив к опечаткам (`rapidfuzz`) и к **неверной раскладке клавиатуры**
  (`Ktybyuhfl` → `Ленинград`). Порог схожести настраивается.
- **Поиск с фильтром по исполнителям** — мультивыбор (чипы в Mini App,
  кнопки с «✅» в боте): показываются треки, у которых есть **все** выбранные
  исполнители. Папки при этом ищутся всегда.
- **Отдельные поиски по разделам:** `/tracks_search` (только аудио),
  `/artists_search`, `/favourites_search`, строка поиска в разделе «Другое».
- **Поиск аудио в самом Telegram** (опционально, через Telethon):
  ищет треки в публичных каналах и импортирует их в ваше хранилище
  в один клик; поддерживается импорт по ссылке `https://t.me/...`.
  Без Telethon поиск отключается, а **пересылка аудио боту работает всегда**.

### Прослушивание

- **В боте** — кнопка «▶️ Прослушать» присылает трек аудиосообщением.
- **В Mini App** — полноценный плеер: очередь, следующий/предыдущий,
  перемотка, повтор, перемешивание, мини-плеер над нижней навигацией.
- **Проиграть всё** — `/play_all` (вся фонотека) и `/play_folder`
  (папка вместе с подпапками). Бот шлёт пачками по 10 треков с паузой
  0,3 с и кнопкой «Ещё 10»; каждый отправленный трек учитывается
  в статистике. В Mini App тем же занимаются кнопки «Воспроизвести всё»
  и «Воспроизвести папку» (эндпоинты `/tracks/play_all`
  и `/folders/{id}/play`).
- Каждое воспроизведение учитывается и мгновенно отражается в статистике.

### Пять разделов статистики

| Раздел | Что показывает |
|---|---|
| 🔥 **Самые часто прослушиваемые** (`top`) | Топ-10 треков по числу прослушиваний |
| 🆕 **Недавно добавленные** (`recent`) | Последние загруженные треки |
| 💤 **Ни разу не проигранные** (`unplayed`) | Треки с нулём прослушиваний |
| 📈 **Часто прослушиваемые** (`frequent`) | От 10 прослушиваний и больше |
| 📉 **Редко прослушиваемые** (`rare`) | От 1 до 5 прослушиваний |

Точные правила — в разделе [20](#20-логика-разделов-статистики).
Команда `/start` сразу показывает топ-10 и кнопки остальных разделов.

### Рекомендации

Две категории — «Популярные» и «Менее известные»: жанры ваших прослушиваний
плюс коллаборативная фильтрация по пользователям с похожими вкусами.
Алгоритм не ходит в интернет и не выдумывает исполнителей: если данных мало,
список честно добивается непрослушанными исполнителями из вашей же библиотеки,
а в ответе приходят `shortfall` и пояснение `note`. Подробно —
раздел [21](#21-рекомендации-как-это-работает).

### Прочее

- Настройки пользователя: автосортировка, границы разделов статистики,
  порог нечёткого поиска — меняются в Mini App и командой `/settings`.
- Многопользовательский режим с изоляцией данных: все запросы к базе
  фильтруются по `user_id`. Доступ можно ограничить белым списком.
- Полностью русский интерфейс бота и Mini App, светлая и тёмная тема
  Telegram, поддержка «безопасных зон» на iPhone.
- **Миграции схемы** в `backend/db/migrations/` применяются автоматически
  при старте и идемпотентны, учёт — в таблице `schema_migrations`
  (см. раздел [5](#5-обновление-с-версии-1-на-версию-2)).
- **Аватарка и профиль бота**: генератор картинки `scripts/make_avatar.py`
  и `scripts/setup_profile.py` для имени и описаний
  (раздел [7](#7-аватарка-и-профиль-бота)).
- **Распознавание исполнителя по аудио — заглушка.**
  `backend/services/recognition.py` содержит настоящий код запросов
  к AudD / ACRCloud / Genius, но без ключей он не выполняется, а на живых
  ключах не проверялся. По умолчанию функция выключена
  (`RECOGNITION_PROVIDER` пуст) и честно отвечает, что распознавание
  не настроено.

## 2. Архитектура

Один процесс Python обслуживает и бота, и веб-приложение.

```
                    ┌───────────────────────────────────────────┐
   Пользователь ──▶ │              Telegram                     │
   (чат с ботом)    │  ┌─────────────┐   ┌────────────────────┐ │
                    │  │  Bot API    │   │ Приватный канал    │ │
                    │  │             │   │ (аудио и файлы)    │ │
                    │  └──────┬──────┘   └─────────┬──────────┘ │
                    └─────────│────────────────────│────────────┘
        polling / webhook     │   copy_message     │ file_id
                    ┌─────────▼────────────────────▼────────────┐
                    │            MusicBox (один процесс)        │
                    │                                           │
                    │  aiogram 3  ──────┐   ┌────── FastAPI     │
                    │  (handlers,       │   │      (REST API,   │
                    │   keyboards,      │   │       stream,     │
                    │   FSM)            │   │       статика)    │
                    │        │          │   │          │        │
                    │        └──► services ◄┘          │        │
                    │   storage · media · metadata · autosort   │
                    │   search · batch_sort · telegram_search   │
                    │   recommendations · recognition (заглушка)│
                    │                  │                │       │
                    │            repositories (aiosqlite)       │
                    │                  │                        │
                    │            ┌─────▼─────┐                  │
                    │            │  SQLite   │ data/musicbox.db │
                    │            │   (WAL)   │ + миграции       │
                    │            └───────────┘                  │
                    └───────────────────┬───────────────────────┘
                                        │ HTTPS
                    ┌───────────────────▼───────────────────────┐
   Пользователь ──▶ │   React Mini App (Vite, HashRouter)       │
   (Mini App)       │   плеер · статистика · папки · заметки    │
                    │   рекомендации · «Другое» · поиск         │
                    └───────────────────────────────────────────┘
```

Ключевые решения:

- **Файлы не хранятся на сервере.** В базе лежит `file_id` сообщения в канале.
  Стриминг в браузер идёт «на лету»: FastAPI получает файл у Bot API через
  `httpx` и отдаёт чанками с поддержкой заголовка `Range` (перемотка).
- **Ссылка на аудио подписана.** `stream_url` содержит HMAC-токен с временем
  жизни; прямой адрес файла в Telegram наружу никогда не отдаётся.
- **API смонтирован дважды** — по путям `/api/...` и `/...`, поэтому работают
  и `GET /api/stats/top`, и `GET /stats/top`.
- **Статика Mini App** отдаётся тем же процессом с `/` и SPA-fallback
  на `index.html`.

### Схема базы данных

Одна SQLite-база (WAL). Все таблицы пользовательских данных содержат `user_id`,
и ни один запрос репозитория не выполняется без условия `user_id = ?`.

| Таблица | Назначение | Что добавила V2 |
|---|---|---|
| `schema_migrations` | Учёт применённых миграций: `version`, `name`, `applied_at` | **новая** |
| `users` | Пользователи Telegram | — |
| `user_settings` | Автосортировка, границы разделов, порог поиска | — |
| `folders` | Папки библиотеки | `parent_folder_id` (вложенность), `section` (`music` / `other`), ключ `UNIQUE (user_id, section, parent_folder_id, normalized_name)` |
| `artists` | Исполнители, отметка «прослушано», папка | `total_plays` — сумма прослушиваний треков исполнителя |
| `albums` | Альбомы (группы) из тегов | — |
| `tracks` | Карточки файлов: метаданные, `file_id`, `storage_message_id`, счётчики | `file_type` (`audio` / `document` / `video` / `video_note` / `voice`), `genre` |
| `track_artists` | Связь «трек ↔ исполнитель»: `position = 0` — основной | **новая** |
| `favourites` | Избранное | — |
| `playlists`, `playlist_tracks` | Плейлисты и порядок треков | — |
| `play_history` | История прослушиваний: `track_id`, `played_at`, `source` | новые значения `source`: `bot_play_all`, `bot_play_folder` |
| `notes`, `note_items` | Заметки и пункты с чекбоксами (`is_done`, `position`) | **новые** |

Индексы V2: `idx_folders_parent`, `idx_folders_section`, `idx_tracks_user_type`,
`idx_track_artists_artist`, `idx_notes_user`, `idx_note_items_note`.

`backend/db/schema.sql` описывает **базовую схему V1** и целиком состоит
из `CREATE … IF NOT EXISTS` — до состояния V2 базу доводят миграции
(раздел [5](#5-обновление-с-версии-1-на-версию-2)).

## 5. Обновление с версии 1 на версию 2

Раздел нужен только тем, у кого **уже есть рабочая база V1**. На пустой базе
миграции просто создают схему V2 целиком, и делать ничего не надо.

### Что меняется в базе

| Миграция | Что делает | Обратима |
|---|---|---|
| `001_baseline.sql` | Базовая схема V1. На существующей базе (есть таблица `tracks`) раннер помечает её применённой и ничего не выполняет | — |
| `002_nested_folders.py` | **Пересоздаёт таблицу `folders`**: добавляет `parent_folder_id` и `section`, меняет `UNIQUE (user_id, normalized_name)` на `UNIQUE (user_id, section, parent_folder_id, normalized_name)` | **Нет** |
| `003_track_artists.sql` | Создаёт `track_artists` и переносит туда текущих исполнителей (`position = 0`) | Да (удалить таблицу) |
| `004_media.sql` | `tracks.file_type`, `tracks.genre`, `artists.total_plays`, индекс `idx_tracks_user_type`, первичный пересчёт `total_plays` | Да (колонки остаются лишними) |
| `005_notes.sql` | Создаёт `notes` и `note_items` | Да (удалить таблицы) |

Данные сохраняются: идентификаторы папок не меняются (`tracks.folder_id`
и `artists.folder_id` продолжают указывать на те же папки), все папки V1
получают `section = 'music'` и `parent_folder_id = NULL`, то есть становятся
корневыми папками раздела «Музыка».

> **Миграция 002 необратима.** Таблица `folders` пересоздаётся целиком
> (`CREATE folders_new` → перелив → `DROP TABLE folders` → `RENAME`), обратной
> миграции нет. Единственный способ вернуться к V1 — **восстановление
> из бэкапа**. Поэтому бэкап перед обновлением обязателен.

### Шаг 1. Остановить сервис и сделать бэкап

```bash
sudo systemctl stop musicbox            # или: docker compose stop
mkdir -p backups
sqlite3 data/musicbox.db ".backup 'backups/musicbox-before-v2.db'"
```

```powershell
# остановите процесс: Ctrl+C в окне с `python -m backend.main`
# либо `docker compose stop`, если запускали в Docker
New-Item -ItemType Directory -Force backups | Out-Null
python -c "import sqlite3,sys; src=sqlite3.connect('data/musicbox.db'); dst=sqlite3.connect(sys.argv[1]); src.backup(dst); dst.close(); src.close()" backups\musicbox-before-v2.db
```

Второй вариант работает без установленного `sqlite3` и безопасен при
включённом WAL. Проверьте копию до обновления:

```bash
sqlite3 backups/musicbox-before-v2.db "PRAGMA integrity_check;"   # ожидается: ok
sqlite3 backups/musicbox-before-v2.db "SELECT COUNT(*) FROM tracks;"
```

Подробнее о бэкапах — раздел
[24](#24-резервное-копирование-и-восстановление-бд).

### Шаг 2. Обновить код и собрать Mini App

```bash
git pull
source .venv/bin/activate
pip install -r requirements.txt
cd frontend && npm ci && npm run build && cd ..
```

```powershell
git pull
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Set-Location frontend; npm ci; npm run build; Set-Location ..
```

Новых обязательных переменных `.env` в V2 нет — старый файл подходит как есть.
Опциональные переменные распознавания описаны в разделе
[9](#9-настройка-env).

### Шаг 3. Запустить — миграции применятся сами

```bash
sudo systemctl start musicbox           # или: docker compose up -d --build
journalctl -u musicbox -n 50 --no-pager
```

`init_db()` при старте вызывает `apply_migrations()`: файлы из
`backend/db/migrations/` применяются по возрастанию номера, каждый —
в своей транзакции, с записью в `schema_migrations`. Повторный запуск ничего
не делает (идемпотентность), отдельной команды запускать не нужно.

В логе при первом старте V2 будет примерно так:

```
INFO | Обнаружена база V1 (таблица tracks уже есть): миграция 001_baseline
       помечена применённой без выполнения
INFO | Применяется миграция 002_nested_folders
INFO | Миграция 002_nested_folders применена
...
INFO | Применены миграции схемы (4): 002_nested_folders, 003_track_artists,
       004_media, 005_notes
INFO | Схема базы данных актуальна
```

Если миграция упадёт, приложение остановится с ошибкой `MigrationError`
и текстом причины — база при этом останется в состоянии до упавшей миграции
(изменения откатываются вместе с транзакцией).

### Шаг 4. Проверить результат

```bash
# какие миграции записаны
sqlite3 data/musicbox.db "SELECT version, name, applied_at FROM schema_migrations ORDER BY version;"

# новые колонки на месте
sqlite3 data/musicbox.db "PRAGMA table_info(folders);"   # ждём parent_folder_id и section
sqlite3 data/musicbox.db "PRAGMA table_info(tracks);"    # ждём file_type и genre

# данные целы
sqlite3 data/musicbox.db "SELECT COUNT(*) FROM tracks;"
sqlite3 data/musicbox.db "SELECT COUNT(*) FROM folders;"
sqlite3 data/musicbox.db "SELECT COUNT(*) FROM track_artists;"
sqlite3 data/musicbox.db "PRAGMA foreign_key_check;"     # пусто — значит связи целы
```

Числа треков и папок должны совпасть с бэкапом, а `track_artists` — с числом
треков, у которых заполнен `artist_id`:

```bash
sqlite3 data/musicbox.db "SELECT COUNT(*) FROM tracks WHERE artist_id IS NOT NULL;"
```

Живая проверка: `curl -s http://localhost:8000/health`, затем в Telegram —
`/tracks`, `/other`, `/notes`, `/recommendations`. В меню «/» должна появиться
31 команда (раздел [17](#17-команды-бота)).

### Откат к версии 1

Отката миграций нет — восстанавливается база из бэкапа, а код возвращается
на предыдущую версию:

```bash
sudo systemctl stop musicbox
cp backups/musicbox-before-v2.db data/musicbox.db
rm -f data/musicbox.db-wal data/musicbox.db-shm
git checkout <тег-или-коммит-V1>
cd frontend && npm ci && npm run build && cd ..
sudo systemctl start musicbox
```

```powershell
docker compose stop
Copy-Item backups\musicbox-before-v2.db data\musicbox.db -Force
Remove-Item data\musicbox.db-wal, data\musicbox.db-shm -ErrorAction SilentlyContinue
git checkout <тег-или-коммит-V1>
docker compose up -d --build
```

Всё, что вы успели добавить, работая на V2, при таком откате теряется —
в бэкапе этого нет. Файлы в канале-хранилище не трогаются ни миграциями,
ни откатом.

Если после обновления что-то выглядит не так (пропали треки, пустые
рекомендации, не применилась миграция) — раздел
[25](#25-устранение-неполадок).

## 6. Создание бота в @BotFather

1. Откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`.

   на `bot` (например, `my_musicbox_bot`).
3. BotFather пришлёт **токен** вида
   `123456789:AAH...` — это значение переменной `BOT_TOKEN`.
   Токен равнозначен паролю бота: не публикуйте его и не кладите в git.
4. Полезные настройки (по желанию):

   ```
   /setdescription   — текст на экране до первого запуска
   /setabouttext     — краткое описание в профиле
   /setuserpic       — аватар бота
   /setprivacy       — Disable, если бот должен видеть сообщения в группах
   ```

5. **Кнопка Mini App.** Когда приложение опубликовано по HTTPS
   (см. раздел [13](#13-публикация-mini-app-nginx--systemd)):

   ```
   /setmenubutton
   → выбрать бота
   → отправить URL, например https://musicbox.example.com
   → отправить подпись кнопки, например: Открыть MusicBox
   ```

   Тот же адрес пропишите в `.env` как `WEBAPP_URL` — тогда бот покажет
   кнопку «🎵 Открыть MusicBox» и в обычной клавиатуре.

6. Команды бота регистрируются автоматически при старте
   (`set_my_commands`), вручную `/setcommands` заполнять не нужно.

   Если хочется опубликовать меню команд сразу, не поднимая всё приложение
   (например, канал ещё не создан и `STORAGE_CHANNEL_ID` не заполнен):

   ```bash
   python -m scripts.setup_commands
   ```

   Скрипту достаточно `BOT_TOKEN`. Он печатает список того, что реально
   зарегистрировалось в Telegram.

7. **Проверка токена.** Убедиться, что токен рабочий, можно одним запросом —
   в ответе будет `username` бота:

   ```bash
   curl -s "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getMe"
   ```

Если токен утёк — `/revoke` в @BotFather, затем обновите `BOT_TOKEN` в `.env`
и перезапустите сервис.

Имя, описания и аватарка — в разделе
[7](#7-аватарка-и-профиль-бота).

## 7. Аватарка и профиль бота

### Что можно сделать программно, а что нельзя

| Что | Как | Автоматизируется |
|---|---|---|
| Отображаемое имя | `setMyName` | Да, `scripts/setup_profile.py` |
| Краткое описание (в профиле и превью) | `setMyShortDescription` | Да, тот же скрипт |
| Описание в пустом чате (до «Запустить») | `setMyDescription` | Да, тот же скрипт |
| **Фото профиля бота (аватарка)** | **только @BotFather → `/setuserpic`** | **Нет** |

**В Telegram Bot API нет метода установки фото профиля бота.** Метода
`setMyPhoto` не существует, а `setChatPhoto` работает только для чатов
и каналов и к профилю бота отношения не имеет. Поэтому аватарка ставится
руками через @BotFather — это единственный способ, никакой скрипт его
не обойдёт.

### Шаг 1. Подготовить картинку

```bash
python -m scripts.make_avatar
```

Команда одинаковая в bash и в PowerShell. Скрипт рисует скрипичный ключ
на градиенте и кладёт результат в два файла:

- `assets/bot_avatar.png` — 512×512, готов для @BotFather;
- `assets/bot_avatar.svg` — тот же рисунок в векторе.

Оба файла уже лежат в репозитории, так что шаг можно пропустить — он нужен,
если хочется другой размер или свой вариант. Зависимостей нет: PNG собирается
стандартной библиотекой, Pillow используется, только если он установлен.

Полезные ключи:

```bash
python -m scripts.make_avatar --size 640          # другой размер
python -m scripts.make_avatar --out my_avatar.png # другой путь
python -m scripts.make_avatar --skip-svg          # только PNG
python -m scripts.make_avatar --renderer builtin  # игнорировать Pillow
```

### Шаг 2. Поставить аватарку через @BotFather

1. Откройте чат с [@BotFather](https://t.me/BotFather).
2. Отправьте `/setuserpic`.
3. Выберите нужного бота в списке.
4. Отправьте `assets/bot_avatar.png` **как фото, а не как файл-документ**:
   скрепка → «Фото или видео» → выбрать `bot_avatar.png`.
   Отправленный документом файл BotFather не примет.
5. Ответ `Success! Profile photo updated.` означает, что всё получилось.

В профиле бота картинка меняется сразу, в списке чатов может обновиться
с задержкой в несколько минут.

### Шаг 3. Имя и описания

```bash
python -m scripts.setup_profile --dry-run   # показать тексты, ничего не менять
python -m scripts.setup_profile             # применить
```

Скрипту достаточно `BOT_TOKEN` (из окружения, из `.env` или из ключа
`--token`); канал-хранилище и база не нужны. Он ставит имя `MusicBox`,
краткое описание и описание для пустого чата, затем читает значения обратно
(`getMyName`, `getMyShortDescription`, `getMyDescription`) и печатает
пошаговую инструкцию по `/setuserpic`.

Ограничения Telegram на длину: имя — 64 символа, краткое описание — 120,
описание — 512. Тексты заданы константами в начале
`scripts/setup_profile.py` (`BOT_NAME`, `BOT_SHORT_DESCRIPTION`,
`BOT_DESCRIPTION`) — правьте их там.

Отдельный язык интерфейса:

```bash
python -m scripts.setup_profile --language-code en
```

## 8. Приватный канал-хранилище

### Шаг 1. Создать канал

Telegram → «Создать канал» → название (например, `MusicBox Storage`) →
тип **Частный канал** → пропустить добавление участников.

### Шаг 2. Добавить бота администратором

1. Откройте канал → «Управление каналом» → «Администраторы» →
   «Добавить администратора».
2. Найдите бота по username и добавьте его.
3. Обязательное право — **«Публикация сообщений»** (`Post Messages`).
   Полезно также включить **«Удаление сообщений»** — тогда бот сможет
   удалять файлы из канала при удалении трека
   (`DELETE /tracks/{id}?delete_from_channel=true`).
   Остальные права можно выключить.

Без права публикации бот не сможет сохранять файлы и будет отвечать
ошибкой сохранения в канал.

### Шаг 3. Узнать ID канала

ID приватного канала — отрицательное число вида `-1001234567890`
(префикс `-100` + внутренний идентификатор).

**Способ 0 — автоматически (рекомендуется).** В проекте есть скрипт, который
сам находит канал и прописывает ID в `.env`. Запустите его **до** того, как
добавите бота в канал (или сразу после — обновления Telegram хранит 24 часа):

```bash
python -m scripts.detect_channel        # ждёт 15 минут
python -m scripts.detect_channel 30     # или укажите своё время в минутах
```

Затем выполните шаги 1–2 выше. В момент, когда бот становится администратором,
Telegram присылает обновление `my_chat_member`, скрипт его ловит, проверяет
право на публикацию и записывает `STORAGE_CHANNEL_ID` в `.env`:

```
INFO | Найден канал-хранилище: «MusicBox Storage», id=-1001234567890
       (администратор с правом публикации)
INFO | STORAGE_CHANNEL_ID=-1001234567890 записан в .env
```

Публиковать сообщение в канале для этого не нужно — достаточно добавить бота.
Заодно скрипт покажет ваш Telegram user id (если вы уже писали боту) —
пригодится для `ALLOWED_USER_IDS`. Смещение обновлений он не подтверждает,
поэтому всё, что вы отправите боту во время ожидания, не потеряется и будет
обработано после запуска.

Скрипт сразу проверяет главную причину поломок: что бот в канале именно
**администратор** и что у него есть право публикации. Если нет — он пишет,
чего не хватает, и продолжает ждать.

> Во время работы скрипта сам бот должен быть **остановлен**. В режиме polling
> он забирает обновления себе, и скрипт не увидит ничего — завершится
> сообщением «Канал так и не появился за отведённое время».

**Способ 1 — переслать сообщение боту-определителю.** Опубликуйте в канале
любое сообщение, перешлите его боту [@userinfobot](https://t.me/userinfobot)
или [@getmyid_bot](https://t.me/getmyid_bot) — в ответе будет `Id` канала.

**Способ 2 — через getUpdates вручную.** То же, что способ 0, но глазами.
Добавьте бота в канал администратором и выполните:

```bash
curl -s "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates" | python -m json.tool
```

```powershell
(Invoke-RestMethod "https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates").result | ConvertTo-Json -Depth 8
```

Найдите блок `"chat": {"id": -1001234567890, "type": "channel", ...}` —
это и есть нужное значение. Он появляется внутри `my_chat_member` сразу после
добавления бота; публиковать сообщение в канале не требуется.

> `getUpdates` возвращает пусто, если бот работает в режиме polling
> (обновления уже забраны процессом) или установлен вебхук. Остановите
> сервис перед запросом или пользуйтесь способом 1.

**Способ 3 — ссылка на сообщение.** В веб-версии Telegram скопируйте ссылку
на любое сообщение канала: `https://web.telegram.org/a/#-1001234567890`
или `https://t.me/c/1234567890/15`. Во втором случае к числу после `/c/`
слева добавьте `-100`: `1234567890` → `-1001234567890`.

### Шаг 4. Записать в .env

```env
STORAGE_CHANNEL_ID=-1001234567890
```

Проверить связку можно так: отправьте боту аудиофайл — он должен появиться
в канале, а бот ответить «Трек сохранён…».

Два пакета опциональны:

- `mutagen` — чтение ID3-тегов у загружаемых файлов. Без него метаданные
  берутся из данных Telegram и имени файла.
- `telethon` — поиск аудио в Telegram. Без него `/tgsearch` отключён,
  пересылка аудио боту работает.

### Инициализация базы

**Ничего делать не нужно** — база создаётся автоматически при первом запуске.
`init_db()` создаёт каталог и файл, затем:

1. применяет миграции из `backend/db/migrations/` по возрастанию номера
   (`001_baseline.sql` → `005_notes.sql`), каждую в своей транзакции,
   с записью в таблицу `schema_migrations`;
2. прогоняет `backend/db/schema.sql` — базовую схему V1 целиком
   из `CREATE … IF NOT EXISTS`, как страховку от частично созданной базы;
3. повторяет проход миграций — на случай таблиц, созданных только что.

Всё это идемпотентно: повторный запуск ничего не меняет. Отдельной команды
«накатить миграции» нет и не требуется. Для базы, созданной ещё до появления
миграций, раннер распознаёт V1 по таблице `tracks` и помечает базовую
миграцию применённой, не выполняя её.

- Файл базы: путь из `DATABASE_PATH`, по умолчанию `data/musicbox.db`
  относительно корня проекта. В Docker — `/app/data/musicbox.db`
  (том `./data` на хосте).
- Рядом появляются `musicbox.db-wal` и `musicbox.db-shm` — это нормально,
  включён режим WAL (журнал упреждающей записи).
- Схема V2: `schema_migrations`, `users`, `user_settings`, `folders`,
  `artists`, `albums`, `tracks`, `track_artists`, `favourites`, `playlists`,
  `playlist_tracks`, `play_history`, `notes`, `note_items` + индексы.
  Подробности — в разделе [2](#2-архитектура).

Посмотреть содержимое:

```bash
sqlite3 data/musicbox.db ".tables"
sqlite3 data/musicbox.db "SELECT COUNT(*) FROM tracks;"
sqlite3 data/musicbox.db "SELECT version, name FROM schema_migrations ORDER BY version;"
```

Обновление базы V1 до V2 — раздел
[5](#5-обновление-с-версии-1-на-версию-2).
Бэкап — в разделе [24](#24-резервное-копирование-и-восстановление-бд).
Чтобы начать с чистого листа, достаточно остановить сервис и удалить
`data/musicbox.db*` (файлы в канале при этом останутся).

| `/notes`, `/notes/:id` | `NotesPage`, `NotePage` | **V2.** Заметки: чекбоксы, порядок пунктов |
| `/recommendations` | `RecommendationsPage` | **V2.** «Популярные» и «Менее известные» + честное пояснение при нехватке данных |

В нижней панели пять вкладок (Главная, Статистика, Папки, Поиск, Плейлисты),
остальные разделы — кнопка «Ещё» и переходы с главной. Карточка трека
в любом списке умеет «✏️ Переименовать» и «🗑 Удалить» с подтверждением.

### Почему здесь нет Tailwind и Material-UI

**Ни Tailwind CSS, ни Material-UI в проекте не используются** — их нет
в `frontend/package.json` и не планируется. Вся стилизация живёт в одном
файле `frontend/src/styles.css` на CSS-переменных темы Telegram
(`--tg-theme-bg-color`, `--tg-theme-text-color`, `--tg-theme-button-color`
и так далее).

Причина простая: Mini App должно выглядеть частью Telegram. Клиент передаёт
цвета текущей темы в `window.Telegram.WebApp.themeParams`, и приложение
подхватывает их напрямую — светлая и тёмная темы переключаются вместе
с темой клиента, без отдельных наборов классов и без пересборки. Utility-классы
Tailwind пришлось бы дублировать под обе темы и держать в синхронизации
с палитрой Telegram, а готовая тема Material-UI ещё и навязала бы свой
внешний вид поверх нативного. Плюс размер бандла: всех зависимостей
фронтенда — React, react-router и dnd-kit.

Из этого следует правило для правок: новый цвет берём из переменной темы
(или объявляем свою рядом с остальными в начале `styles.css`), а не пишем
хардкодом `#ffffff`.

## 12. Запуск: polling и webhook

Точка входа одна:

```bash
python -m backend.main
```

Дополнительные режимы (полезны, если бот и API разнесены по процессам):

```bash
python -m backend.main --api-only    # только веб-сервер, без обработки апдейтов
python -m backend.main --bot-only    # только бот (long polling), без веб-сервера
```

### Polling (по умолчанию)

Бот сам опрашивает Telegram. Не нужны домен, сертификат и открытые порты —
подходит для локальной разработки и любого VPS.

```env
BOT_MODE=polling
```

Опрос запускается фоновой задачей внутри `lifespan` FastAPI и корректно
останавливается вместе с приложением.

### Webhook

Telegram сам присылает обновления на ваш адрес. Меньше задержка, меньше
исходящего трафика — но нужен публичный HTTPS.

```env
BOT_MODE=webhook
WEBHOOK_BASE_URL=https://musicbox.example.com
WEBHOOK_PATH=/telegram/webhook
WEBHOOK_SECRET=длинная-случайная-строка
```

Требования Telegram к HTTPS:

- порт **443**, 80, 88 или 8443;
- **валидный** сертификат (Let's Encrypt подойдёт), самоподписанный —
  только с ручной загрузкой публичного ключа, не рекомендуется;
- полная цепочка сертификатов (`fullchain.pem`), TLS 1.2+;
- адрес должен резолвиться из интернета (не `localhost`, не серый IP).

При старте приложение само вызывает `setWebhook` на
`{WEBHOOK_BASE_URL}{WEBHOOK_PATH}` и передаёт `secret_token`; входящие
запросы без правильного заголовка отбрасываются. При остановке вебхук
снимается.

Проверить состояние:

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo" | python -m json.tool
```

Полезно смотреть поля `url`, `pending_update_count`, `last_error_message`.
Снять вебхук вручную:

```bash
curl -s "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"
```

> Один токен — один режим. Если раньше был вебхук, а вы переключились
> на polling, приложение снимет вебхук само; иначе Telegram будет отвечать
> ошибкой «can't use getUpdates method while webhook is active».

## 13. Публикация Mini App (nginx + systemd)

Чтобы Telegram открыл Mini App, нужен домен с валидным HTTPS. План:
`nginx` терминирует TLS и проксирует на `127.0.0.1:8000`, а `systemd`
держит процесс живым.

### Шаг 1. Сертификат

```bash
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d musicbox.example.com
```

### Шаг 2. nginx

`/etc/nginx/sites-available/musicbox`:

```nginx
server {
    listen 80;
    server_name musicbox.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name musicbox.example.com;

    ssl_certificate     /etc/letsencrypt/live/musicbox.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/musicbox.example.com/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # Аудио отдаётся потоком, файлы могут быть крупными.
    client_max_body_size 60m;

    access_log /var/log/nginx/musicbox.access.log;
    error_log  /var/log/nginx/musicbox.error.log;

    # Статика Mini App: отдаём напрямую с диска (быстрее, чем через приложение).
    location /assets/ {
        alias /opt/musicbox/frontend/dist/assets/;
        expires 30d;
        access_log off;
        add_header Cache-Control "public, immutable";
    }

    # Всё остальное — в приложение: API, стрим аудио, вебхук, index.html.
    location / {
        proxy_pass         http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;

        proxy_set_header   Range             $http_range;
        proxy_set_header   If-Range          $http_if_range;

        proxy_send_timeout 300s;
    }
}
```

## 15. Ограничение 20 МБ и локальный Bot API server

Публичный Bot API накладывает жёсткие лимиты:

| Операция | Лимит | Где проявляется |
|---|---|---|
| Скачивание файла ботом (`getFile`) | **20 МБ** | Стриминг в Mini App, импорт из поиска |
| Отправка файла ботом | **50 МБ** | Пересылка трека в чат |
| Загрузка от пользователя боту | 2 ГБ (4 ГБ у Premium) | Приём аудио — работает всегда |

Что это значит на практике:

- **Сохранить в канал** можно трек любого размера: бот копирует сообщение,
  файл физически не проходит через сервер.
- **Проиграть в Mini App** и **импортировать из поиска** можно файлы
  до 20 МБ (примерно 20 минут mp3 320 kbps). При превышении приложение
  вернёт понятную ошибку с подсказкой, а трек всё равно останется
  в библиотеке и будет доступен прямо в Telegram.
- Порог задаётся переменной `MAX_DOWNLOAD_SIZE` (по умолчанию `20971520`).

### Как снять ограничение

Поднимите **локальный Bot API server** ([telegram-bot-api](https://github.com/tdlib/telegram-bot-api)) —
у него лимит скачивания 2000 МБ, отправки 2000 МБ.

1. Получите `api_id` и `api_hash` на <https://my.telegram.org>
   (раздел «API development tools»).
2. Запустите сервер, например в Docker:

   ```bash
   docker run -d --name telegram-bot-api \
     -p 8081:8081 \
     -e TELEGRAM_API_ID=<api_id> \
     -e TELEGRAM_API_HASH=<api_hash> \
     -v telegram-bot-api-data:/var/lib/telegram-bot-api \
     aiogram/telegram-bot-api:latest --local
   ```

3. Пропишите в `.env`:

   ```env
   TELEGRAM_API_BASE=http://localhost:8081
   MAX_DOWNLOAD_SIZE=2097152000
   ```

4. Перезапустите MusicBox. Перед первым запросом стоит выполнить `logOut`
   на публичном Bot API, чтобы токен «переехал» на локальный сервер:

   ```bash
   curl -s "https://api.telegram.org/bot<ТОКЕН>/logOut"
   ```

> Локальный сервер должен быть доступен процессу MusicBox по указанному
> адресу; наружу его публиковать не нужно. В Docker Compose добавьте сервис
> в ту же сеть и укажите `TELEGRAM_API_BASE=http://telegram-bot-api:8081`.

## 16. Поиск аудио в Telegram (Telethon)

Боты не умеют искать сообщения в чужих каналах — это возможно только
от имени обычного аккаунта. Поэтому для функции «найти трек в Telegram
и добавить к себе» используется библиотека **Telethon** и ваш личный
аккаунт (в режиме только чтения: поиск и скачивание).

**Без Telethon всё остальное работает**: вы просто пересылаете боту аудио
из любого канала или чата, и он сохраняет трек в хранилище, разбирает теги
и раскладывает по папкам. Команда `/tgsearch` в этом случае вежливо
сообщает, что поиск не настроен.

### Шаг 1. Получить API_ID и API_HASH

1. Откройте <https://my.telegram.org> и войдите по номеру телефона.
2. Раздел **API development tools** → заполните форму
   (App title: `MusicBox`, Short name: `musicbox`, Platform: `Desktop`).
3. Скопируйте **App api_id** (число) и **App api_hash** (32 символа).

### Шаг 2. Получить строку сессии

```bash
pip install telethon
python scripts/get_telethon_session.py
```

```powershell
pip install telethon
python scripts\get_telethon_session.py
```

Скрипт спросит `api_id`, `api_hash` и номер телефона, попросит код из
Telegram (и пароль двухфакторной аутентификации, если он включён), после
чего напечатает длинную строку сессии. Скрипт ничего не сохраняет и никуда
не отправляет — строка только выводится в консоль.

### Шаг 3. Заполнить .env

```env
TELEGRAM_SEARCH_ENABLED=true
TG_API_ID=1234567
TG_API_HASH=0123456789abcdef0123456789abcdef
TG_SESSION_STRING=1BQANOTEuMTA4LjU2...
TG_SEARCH_CHATS=musicchannel,best_music_archive
```

`TG_SEARCH_CHATS` — каналы, по которым идёт поиск по умолчанию (юзернеймы
через запятую, без `@`). Для отдельного запроса список можно переопределить
параметром `chats` у эндпоинта `GET /api/search/telegram`; если переменная
пуста, поиск идёт по каналам, доступным аккаунту из строки сессии.

Перезапустите сервис. Теперь доступны `/tgsearch <запрос>`, вкладка поиска
по Telegram в Mini App и импорт по ссылке вида `https://t.me/<канал>/<id>`.

> **Строка сессии равнозначна доступу к аккаунту.** Храните её как пароль:
> только в `.env` с правами `600`, никогда в git, никогда в скриншотах.
> Отозвать можно в Telegram → Настройки → Устройства → завершить сеанс.
> Соблюдайте авторские права и правила Telegram: импортируйте только то,
> что имеете право использовать.

- **аудиофайл или документ с аудио** — сохраняет в канал и в библиотеку

- **документ, видео, кружочек, голосовое** — сохраняет так же, но в раздел
  «Другое» (раздел [19](#19-разделы-треки-и-другое));

  нераспределённые по папкам: создать новую, добавить в существующую, указать
  количество (сервис `batch_sort`);
- **текст** в режиме ожидания ввода (FSM) — имя новой папки, название
  плейлиста, пункт заметки, поисковый запрос.

кнопки «◀️ N/M ▶️», у каждого трека — «▶️ Прослушать», «⭐ В избранное»,
«➕ В плейлист».

## 18. API

### Двойное монтирование

Все маршруты подключены **дважды**: с префиксом `/api` и без него.
Работают и `GET /api/stats/top`, и `GET /stats/top` — вторая форма нужна
для совместимости и ручной отладки, первая используется фронтендом
(`VITE_API_BASE=/api`). Статика Mini App монтируется последней на `/`,
поэтому не перекрывает API.

### Авторизация

- **Обычные запросы** авторизуются по `initData` Telegram WebApp.
  Фронтенд шлёт его в заголовке `X-Telegram-Init-Data` (поддерживается
  и `Authorization: tma <initData>`). Сервер проверяет HMAC-подпись
  ключом, производным от `BOT_TOKEN`, и возраст `auth_date`
  (не старше `INIT_DATA_TTL`). Невалидные данные → `401`.
  Если задан `ALLOWED_USER_IDS` и пользователя в нём нет → `403`.
  При `DEV_MODE=true` и отсутствии заголовка запрос выполняется
  от `DEV_USER_ID`.
- **Стрим и обложки** авторизуются подписанной ссылкой: параметр
  `?token=...` вида `user_id.track_id.exp.HMAC`. Такой токен живёт
  `STREAM_TOKEN_TTL` секунд и годится только для одного трека — это нужно,
  чтобы `<audio src>` работал без заголовков. Прямой адрес файла
  в Telegram наружу не отдаётся никогда.

## 19. Разделы Треки и Другое

В V2 бот принимает не только музыку. Всё, что присылают, попадает в одну
таблицу `tracks`, а различает содержимое колонка `file_type`.

### Что куда попадает

| `file_type` | Значок | Что это | Раздел |
|---|---|---|---|
| `audio` | 🎵 | Аудиосообщение Telegram **и** документ с аудио внутри | **Треки** |
| `document` | 📄 | Любой другой файл: pdf, zip, картинка-документ | Другое |
| `video` | 🎬 | Видеофайл | Другое |
| `video_note` | ⭕ | «Кружочек» — видеосообщение | Другое |
| `voice` | 🎤 | Голосовое сообщение | Другое |

Правило одно: **раздел «Треки» — это `file_type = 'audio'`, раздел «Другое» —
все остальные типы.**

Тип определяется при загрузке в `backend/services/media.py`
(`detect_file_type`) в порядке
`audio` → `voice` → `video_note` → `video` → `document`.
Важный частный случай: **mp3, присланный «файлом»** (как документ),
считается аудио — если у документа mime-тип `audio/*` или знакомое
аудиорасширение, он попадает в «Треки», а не в «Другое». Так mp3 из файлового
менеджера и mp3 из плеера оказываются в одном месте.

Неизвестное значение `file_type` нормализуется в `audio` — поэтому база V1,
где колонки не было вовсе, после миграции `004_media.sql` целиком остаётся
в разделе «Треки» (`DEFAULT 'audio'`).

### Что из этого следует

- **Статистика — только про музыку.** Все пять разделов, `/stats/*` и счётчики
  считают исключительно `file_type = 'audio'`. Кружочек или pdf не испортят
  топ прослушиваний.
- **Списки треков по умолчанию тоже.** `GET /api/tracks` без параметров
  отдаёт только аудио; `file_type=other` — всё не-аудио, `file_type=all` —
  без фильтра.
- **Папки живут в двух деревьях.** `folders.section = 'music'` — папки
  музыки, `'other'` — папки раздела «Другое». Перенести папку из одного
  раздела в другой нельзя.
- **Отдача файла отличается.** Аудио отдаётся потоком для `<audio>`
  (`/tracks/{id}/stream`), файлы «Другого» — через
  `/other/{id}/download` с заголовком `Content-Disposition: attachment`
  (или `inline=true` для просмотра прямо в браузере). Токен доступа один
  и тот же — подписанный stream-токен.
- **Конвертации нет.** Файл сохраняется и отдаётся как есть, с исходным
  `mime_type`; бот выбирает метод отправки по типу (`send_audio`,
  `send_document`, `send_video`, `send_video_note`, `send_voice`).

### Где смотреть

| Где | Треки | Другое |
|---|---|---|
| Бот | `/tracks`, `/tracks_search` | `/other` |
| Mini App | страница `/tracks` | страница `/other` |
| API | `GET /api/tracks` (по умолчанию) | `GET /api/other`, `GET /api/other/folders` |

## 20. Логика разделов статистики

### Как учитывается прослушивание

Счётчик увеличивается **одной атомарной операцией** `register_play`, которая:

1. `play_count = play_count + 1` и `last_played_at = CURRENT_TIMESTAMP`
   у трека;
2. добавляет запись в `play_history` (`track_id`, `played_at`, `source`);
3. помечает исполнителя прослушанным (`artists.is_listened = 1`,
   `listened_at = CURRENT_TIMESTAMP`) и увеличивает `artists.total_plays`
   (V2), если у трека есть `artist_id`.

Источники (`source` в `play_history`):

| Источник | Когда | Значение |
|---|---|---|
| Бот | нажата «▶️ Прослушать» — бот отправил трек аудиосообщением | `bot` |
| Плейлист в боте | «▶️ Проиграть плейлист» — засчитывается **каждый** отправленный трек | `bot_playlist` |
| `/play_all` | **V2.** Отправка всей фонотеки пачками по 10 — засчитывается каждый трек | `bot_play_all` |
| `/play_folder` | **V2.** Отправка папки вместе с подпапками — засчитывается каждый трек | `bot_play_folder` |
| Веб-плеер | Mini App начинает воспроизведение (`POST /tracks/{id}/play`) | `web` |

В веб-плеере прослушивание засчитывается и при **автопереходе** к следующему
треку очереди — так плейлист целиком отражается в статистике. Если запрос
`play` не прошёл (нет сети), воспроизведение не блокируется: ошибка просто
логируется.

После каждого учтённого прослушивания фронтенд увеличивает счётчик
`playVersion`, а страницы статистики держат его в зависимостях загрузки —
поэтому разделы обновляются **в реальном времени**, без ручного обновления.

### Правила разделов

| Ключ | Заголовок | Условие | Сортировка | Лимит по умолчанию |
|---|---|---|---|---|
| `top` | Самые часто прослушиваемые | `play_count > 0` | `play_count DESC`, затем `last_played_at DESC`, затем `id DESC` | `TOP_LIMIT` = **10** |
| `recent` | Недавно добавленные | без условия (вся библиотека) | `created_at DESC`, затем `id DESC` | `RECENT_LIMIT` = **20** |
| `unplayed` | Ни разу не проигранные | `play_count = 0` | `created_at DESC` | 50 |
| `frequent` | Часто прослушиваемые | `play_count >= FREQUENT_THRESHOLD` (**≥ 10**) | `play_count DESC` | 50 |
| `rare` | Редко прослушиваемые | `RARE_MIN <= play_count <= RARE_MAX` (**1…5**, включительно) | `play_count DESC` | 50 |

Границы `frequent` и `rare` берутся из **настроек пользователя**
(`/settings` или Mini App), а если пользователь их не менял — из `.env`.
Это значит, что разделы можно подогнать под свою фонотеку: например,
считать частым трек от 25 прослушиваний.

Разделы **намеренно пересекаются и не покрывают всё**:

- трек с `play_count = 0` попадает только в `unplayed`;
- трек с 1–5 прослушиваниями — в `rare` (и, возможно, в `top`);
- трек с 6–9 прослушиваниями не попадает ни в `rare`, ни в `frequent` —
  это «серая зона» между настройками, и это нормально;
- трек с 10+ — в `frequent` (и, скорее всего, в `top`);
- `recent` показывает всю библиотеку в порядке добавления, независимо
  от прослушиваний.

### Счётчики (`GET /api/stats/counts`)

```json
{
  "total": 342,        "total_plays": 1180,
  "top": 210,          "recent": 342,
  "unplayed": 132,     "frequent": 24,
  "rare": 158,         "favourites": 41,
  "folders": 19,       "artists": 63
}
```

Два счётчика читаются не буквально:

- `"recent"` — это **общее число треков** (раздел показывает всю библиотеку
  по дате добавления);
- `"top"` — число треков, у которых `play_count > 0`, то есть потенциальный
  размер топа, а не 10.

Все счётчики и разделы считают только `file_type = 'audio'` — файлы раздела
«Другое» в статистику не входят (раздел
[19](#19-разделы-треки-и-другое)).

## 21. Рекомендации: как это работает

Где смотреть: команда `/recommendations` в боте, страница `/recommendations`
в Mini App, эндпоинт `GET /api/recommendations?limit=15` (по умолчанию 15,
максимум 50 в каждой категории).

### Откуда берутся данные

Только из вашей же базы: `artists.total_plays`, `tracks.genre` и история
прослушиваний **всех** пользователей этой установки, агрегированная по
нормализованному имени исполнителя. Никакие внешние сервисы не опрашиваются,
несуществующие исполнители не выдумываются.

### Алгоритм

1. **Что вы уже слушали** — исполнители с `total_plays > 0`. Если таких нет,
   подбор не запускается: обе категории пустые, в `note` — «Послушайте
   несколько треков, и я подберу похожих исполнителей».
2. **Любимые жанры** — топ-5 жанров по числу прослушиваний ваших треков.
3. **Кандидаты** (до 200 из каждого источника, всё прослушанное исключается):
   - **коллаборативная фильтрация** — исполнители тех пользователей, у кого
     есть общие с вами прослушанные исполнители;
   - **по жанрам** — исполнители из ваших топ-5 жанров.
4. **Скоринг:**
   `3 × совпадение_жанра + 2 × число_общих_слушателей + 1 × нормированная_популярность`.
5. **Две категории без пересечений** — исполнитель попадает ровно в одну:
   - **«Популярные»** — кандидаты с наибольшим числом прослушиваний в базе;
   - **«Менее известные»** — с наименьшим, но **ненулевым** числом
     прослушиваний.
6. **Деградация** — если кандидатов меньше `limit`, списки добиваются
   непрослушанными исполнителями **из вашей же библиотеки** с пометкой
   `«из вашей библиотеки»`, а в ответ кладутся `shortfall` и `note`.

У каждой рекомендации есть `reason` — почему она здесь: `жанр: rock`,
`слушают вместе с «Кино»`, `слушают те, у кого похожие вкусы`,
`часто слушают другие пользователи` или `из вашей библиотеки`.
Плюс `sample_track_ids` — до 5 треков-примеров и `local_artist_id`, если
исполнитель уже есть в вашей библиотеке.

### Честно про ограничения

Рекомендации — это статистика по базе, а не музыкальный сервис. На маленьких
данных они работают ровно настолько, насколько данных хватает:

- **Нужна многопользовательская база.** Коллаборативная фильтрация ищет
  пользователей с похожими вкусами. Если пользователь один, этот источник
  не даёт ничего, и остаются только жанры.
- **«Не менее 15» не гарантируется.** На пустой или почти пустой базе набрать
  по 15 новых исполнителей в каждую категорию невозможно. Вместо выдумывания
  ответ честно сообщает недобор:

  ```json
  {
    "popular": ["… 6 рекомендаций, 4 из них — из вашей библиотеки …"],
    "underground": ["… 3 рекомендации, 2 из них — из вашей библиотеки …"],
    "shortfall": {"popular": 9, "underground": 12},
    "note": "Пока в базе мало пользователей и прослушиваний, поэтому набрать по 15 новых исполнителей в обе категории не удалось. Добавил непрослушанных исполнителей из вашей библиотеки: «Популярные» — 4, «Менее известные» — 2. До 15 позиций не хватает: «Популярные» — 9, «Менее известные» — 12."
  }
  ```

  (`popular` и `underground` — массивы объектов `RecommendationOut`, здесь они
  сокращены.)

- **Позиции с `reason = "из вашей библиотеки"` — это не открытие**, а честная
  замена: исполнитель, которого вы загрузили, но ещё ни разу не слушали.
- **Без жанров подбор слабее.** `tracks.genre` заполняется из тегов; у файлов
  без тегов жанра нет, и жанровый источник кандидатов молчит.
- **Категория «Менее известные» может быть пустой** даже при непустых
  «Популярных»: в неё берутся только кандидаты с ненулевыми прослушиваниями,
  а таких в маленькой базе почти нет.

Проверить, что именно вернул сервер:

```bash
curl -s "http://localhost:8000/api/recommendations?limit=15" | python -m json.tool
```

Если `note` не `null` — читайте его, там написана причина.

## 23. Безопасность

**Валидация initData.** Каждый запрос Mini App проверяется по алгоритму
Telegram: `secret = HMAC_SHA256(key="WebAppData", msg=BOT_TOKEN)`, затем
подпись строки `data_check_string` сравнивается через `hmac.compare_digest`
(защита от атак по времени). Дополнительно проверяется `auth_date`:
данные старше `INIT_DATA_TTL` отклоняются, чтобы перехваченный `initData`
нельзя было переиспользовать бесконечно.

**Подписанные stream-токены.** Тег `<audio>` не умеет слать заголовки,
поэтому ссылка на аудио содержит токен `user_id.track_id.exp.HMAC`,
подписанный `SECRET_KEY`. Токен действителен `STREAM_TOKEN_TTL` секунд
и только для одного трека одного пользователя. Настоящий адрес файла
в Telegram (`https://api.telegram.org/file/bot<ТОКЕН>/…`) содержит токен
бота и **наружу не отдаётся никогда** — сервер проксирует поток сам.

**`ALLOWED_USER_IDS`.** Белый список Telegram-ID (через запятую).
Если он задан, все остальные получают `403` и в API, и в боте.
Для личного хранилища укажите здесь только свой ID:

```env
ALLOWED_USER_IDS=123456789
```

Пустое значение означает «доступ открыт всем» — данные при этом
всё равно изолированы: каждый пользователь видит только свою библиотеку,
так как все запросы к базе фильтруются по `user_id`.

**Изоляция данных.** Ни один репозиторий не выполняет запрос без условия
`user_id = ?`. Подобрать чужой `track_id` бесполезно: трек не найдётся.

**Хранение секретов.** `BOT_TOKEN`, `SECRET_KEY`, `WEBHOOK_SECRET`,
`TG_SESSION_STRING` живут только в `.env`; файл в `.gitignore`.
На сервере ограничьте права:

```bash
chmod 600 /opt/musicbox/.env
chown musicbox:musicbox /opt/musicbox/.env
```

В коде секретов нет — всё читается через `backend.config.settings`.
Не выкладывайте `.env` в чаты и скриншоты. При утечке: `/revoke`
в @BotFather, новый `SECRET_KEY` (старые ссылки на стрим станут
недействительны — это ожидаемо), завершение Telethon-сессии в настройках
Telegram.

**Приватность канала.** Канал-хранилище должен оставаться **частным**
и без участников, кроме вас и бота. Не выдавайте на него ссылку-приглашение
и не публикуйте `file_id` — по нему любой бот сможет получить файл.

**Прочее.** `WEBHOOK_SECRET` отсекает подделанные запросы к вебхуку;
`ThrottlingMiddleware` (~0.4 с на пользователя) гасит флуд;
`DEV_MODE=true` полностью отключает проверку `initData`, поэтому
в продакшене он обязан быть `false`; `CORS_ORIGINS` в проде разумно
сузить до своего домена вместо `*`.

## 24. Резервное копирование и восстановление БД

Вся библиотека (кроме самих аудиофайлов — они в Telegram) лежит в одном
файле SQLite. Резервная копия — это копия базы.

**Важно:** при включённом WAL нельзя копировать `musicbox.db` обычным `cp`
во время работы — рядом лежат `musicbox.db-wal` и `musicbox.db-shm`
с ещё не слитыми изменениями. Используйте штатные средства SQLite,
они безопасны «на горячую».

### Бэкап

```bash
mkdir -p backups
sqlite3 data/musicbox.db ".backup 'backups/musicbox-$(date +%F-%H%M).db'"
```

Без `sqlite3` в системе — средствами Python (работает везде, включая Windows):

```bash
python -c "import sqlite3,datetime,pathlib; pathlib.Path('backups').mkdir(exist_ok=True); src=sqlite3.connect('data/musicbox.db'); dst=sqlite3.connect('backups/musicbox-'+datetime.datetime.now().strftime('%Y%m%d-%H%M')+'.db'); src.backup(dst); dst.close(); src.close()"
```

```powershell
New-Item -ItemType Directory -Force backups | Out-Null
$stamp = Get-Date -Format 'yyyyMMdd-HHmm'
python -c "import sqlite3,sys; src=sqlite3.connect('data/musicbox.db'); dst=sqlite3.connect(sys.argv[1]); src.backup(dst); dst.close(); src.close()" "backups/musicbox-$stamp.db"
```

Альтернатива — компактная копия одним запросом (тоже безопасна онлайн):

```bash
sqlite3 data/musicbox.db "VACUUM INTO 'backups/musicbox-latest.db';"
```

### Ежедневный бэкап по расписанию

`crontab -e` (хранить 14 последних копий):

```cron
15 4 * * * /usr/bin/sqlite3 /opt/musicbox/data/musicbox.db ".backup '/opt/musicbox/backups/musicbox-$(date +\%F).db'" && find /opt/musicbox/backups -name 'musicbox-*.db' -mtime +14 -delete
```

Windows — «Планировщик заданий» с действием
`powershell.exe -File C:\MusicBox\backup.ps1`, где скрипт выполняет
команду из блока выше.

Для Docker всё то же самое, но по пути тома:

```bash
docker compose exec musicbox python -c "import sqlite3; s=sqlite3.connect('/app/data/musicbox.db'); d=sqlite3.connect('/app/data/backup.db'); s.backup(d); d.close(); s.close()"
```

### Восстановление

```bash
sudo systemctl stop musicbox                     # или docker compose stop
cp backups/musicbox-2026-09-06.db data/musicbox.db
rm -f data/musicbox.db-wal data/musicbox.db-shm  # остатки старого журнала
sudo systemctl start musicbox
```

```powershell
docker compose stop
Copy-Item backups\musicbox-20260906-0415.db data\musicbox.db -Force
Remove-Item data\musicbox.db-wal, data\musicbox.db-shm -ErrorAction SilentlyContinue
docker compose start
```

Проверка целостности копии:

```bash
sqlite3 backups/musicbox-2026-09-06.db "PRAGMA integrity_check;"   # ожидается: ok
sqlite3 backups/musicbox-2026-09-06.db "SELECT COUNT(*) FROM tracks;"
```

> Файлы в приватном канале не удаляются при потере базы — но восстановить
> по ним библиотеку автоматически нельзя (связь «трек ↔ сообщение» хранится
> только в базе). Делайте бэкапы.

## 25. Устранение неполадок

### Бот не сохраняет треки в канал

Симптомы: «Не удалось сохранить трек в хранилище», в логах —
`StorageError`, `CHAT_WRITE_FORBIDDEN`, `chat not found`.

- Бот действительно **администратор канала** с правом
  **«Публикация сообщений»**? Права нужно выдавать именно администратору,
  участником канала бот быть не может.
- `STORAGE_CHANNEL_ID` начинается с `-100` и введён без пробелов?
  ID супергруппы или личного чата не подойдёт.
- Канал не удалён и бот из него не исключён?
- Проверьте вручную:

  ```bash
  curl -s "https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=-1001234567890&text=test"
  ```

  Ответ `{"ok":true,...}` означает, что доступ есть и дело в другом.

### В Mini App «401» или «Ошибка авторизации»

- Приложение открыто **из Telegram** (кнопка меню или кнопка в чате),
  а не набором адреса в браузере? Вне Telegram `initData` пустой.
- Совпадает ли `BOT_TOKEN` в `.env` с ботом, из которого открыто
  приложение? `initData` подписан токеном конкретного бота.
- Не истёк ли `initData`: если вкладка провисела дольше `INIT_DATA_TTL`
  (сутки по умолчанию), закройте и откройте Mini App заново.
- Проверьте время на сервере — расхождение часов ломает проверку
  `auth_date`: `timedatectl status`, при необходимости включите NTP.
- Для отладки в обычном браузере: `DEV_MODE=true` и `DEV_USER_ID=<ваш id>`
  (только на локальной машине!).
- `403` вместо `401` означает, что ваш ID не входит в `ALLOWED_USER_IDS`.

### Трек не воспроизводится

- **Файл больше 20 МБ** — лимит `getFile` публичного Bot API.
  Проверьте `file_size` трека; решение — локальный Bot API server
  (раздел [15](#15-ограничение-20-мб-и-локальный-bot-api-server)).
- **Истёк stream-токен** (`401` на `/tracks/{id}/stream`): ссылка живёт
  `STREAM_TOKEN_TTL` секунд. Обновите страницу — токены выдаются заново.
- **Меняли `SECRET_KEY`** — все ранее выданные ссылки стали
  недействительными; достаточно перезагрузить Mini App.
- **`502` от API** — Telegram не отдал файл: проверьте логи,
  сеть сервера и доступность `api.telegram.org`.
- **Нет перемотки, аудио «дёргается» через nginx** — в конфиге должны быть
  `proxy_buffering off` и проброс заголовка `Range`
  (см. раздел [13](#13-публикация-mini-app-nginx--systemd)).
- **Формат не поддерживается браузером**: `.flac` и `.wma` играют не везде;
  в самом Telegram трек при этом откроется нормально.

### Поиск по Telegram недоступен

Сообщение «Поиск по Telegram не настроен. Перешлите аудио боту…»
или `503` на `/api/search/telegram`.

- `TELEGRAM_SEARCH_ENABLED=true`?
- Установлен ли Telethon: `pip install telethon`?
- Заполнены `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING`?
- Строка сессии не отозвана (Telegram → Настройки → Устройства)?
  Если отозвана — сгенерируйте заново:
  `python scripts/get_telethon_session.py`.
- Канал из `TG_SEARCH_CHATS` действительно публичный и доступен вашему
  аккаунту? Приватные каналы, где вас нет, искать невозможно.
- **Пересылка аудио боту работает всегда** и не требует Telethon —
  это штатный обходной путь.

### Миграция не применилась

Симптомы: после обновления бот падает с `MigrationError`, в Mini App
`500`, в логах — `no such column: t.file_type`, `no such table: notes`
или `no such column: parent_folder_id`.

Сначала посмотрите, что база о себе думает:

```bash
sqlite3 data/musicbox.db "SELECT version, name, applied_at FROM schema_migrations ORDER BY version;"
```

- **Таблицы `schema_migrations` нет вовсе** — приложение ни разу не стартовало
  на новом коде. Запустите его: миграции применяются автоматически при старте
  (`init_db` → `apply_migrations`), отдельной команды нет.
- **Записи есть, но не все** — упала конкретная миграция. Её номер и причина
  будут в логе: `journalctl -u musicbox -n 200 --no-pager` или
  `docker compose logs --tail=200 musicbox`. Изменения упавшей миграции
  откачены, база осталась в предыдущем состоянии.
- **`database is locked`** — база занята вторым процессом (например, сервис
  systemd и запуск руками). Оставьте один процесс и перезапустите.
- **`attempt to write a readonly database`** — нет прав на файл или каталог:
  `chown musicbox:musicbox data/ && chmod 644 data/musicbox.db`.
- **`FOREIGN KEY constraint failed` в миграции 002** — в базе уже были битые
  ссылки (правили её извне с выключенными внешними ключами). Найдите их:
  `sqlite3 data/musicbox.db "PRAGMA foreign_key_check;"`, почините или
  восстановитесь из бэкапа.

После починки просто перезапустите приложение — миграции идемпотентны,
применится только то, чего нет в `schema_migrations`. Если ничего не помогает,
возвращайтесь на бэкап: раздел
[5](#5-обновление-с-версии-1-на-версию-2).

### После обновления «пропали» треки

Симптом: в `/tracks` или на странице «Треки» видно меньше файлов, чем было
в V1, но `SELECT COUNT(*) FROM tracks` показывает прежнее число.

Скорее всего, ничего не пропало — сработал фильтр по `file_type`. Раздел
«Треки» показывает только `file_type = 'audio'`, всё остальное уехало
в «Другое» (раздел [19](#19-разделы-треки-и-другое)).
Проверьте раскладку:

```bash
sqlite3 data/musicbox.db "SELECT file_type, COUNT(*) FROM tracks GROUP BY file_type;"
```

- Все записи с `file_type='audio'`, а списки всё равно короче — дело
  не в типах: проверьте фильтр папки (`folder_id`) и раздел (`section`),
  а не в том, что треки удалились.
- Часть записей получила не тот тип (например, mp3 оказался `document`) —
  это возможно только для файлов, загруженных уже на V2 с неопознанным
  mime-типом. Вернуть в «Треки» можно вручную:

  ```bash
  sqlite3 data/musicbox.db "UPDATE tracks SET file_type='audio' WHERE id=<id трека>;"
  ```

  Делайте это на остановленном сервисе и после бэкапа.
- Смотреть всю библиотеку без фильтра: `GET /api/tracks?file_type=all`.

Миграция `004_media.sql` ставит всем существующим записям `file_type='audio'`
(`DEFAULT 'audio'`), поэтому после обновления с V1 вся старая библиотека
целиком остаётся в «Треках».

### Рекомендации пустые или их мало

Это штатное поведение на маленькой базе, а не ошибка. Смотрите поле `note`
в ответе — там написана причина:

```bash
curl -s "http://localhost:8000/api/recommendations?limit=15" | python -m json.tool
```

- **Обе категории пустые, `note` про «Послушайте несколько треков»** —
  у вас нет ни одного прослушивания. Послушайте что-нибудь: отметка ставится
  и из бота («▶️ Прослушать»), и из плеера Mini App.
- **Списки короче 15 и заполнены пометкой «из вашей библиотеки»** — кандидатов
  не хватило, сработала деградация. Причина в `note`: «в базе мало
  пользователей и прослушиваний». «Не менее 15» на такой базе физически
  невозможно — раздел [21](#21-рекомендации-как-это-работает).
- **«Менее известные» пустые, «Популярные» есть** — в «Менее известные»
  попадают только исполнители с ненулевыми прослушиваниями; в маленькой базе
  их может не быть вовсе.
- **Жанровый подбор молчит** — у треков не заполнен `genre` (нет тегов):
  `sqlite3 data/musicbox.db "SELECT COUNT(*) FROM tracks WHERE genre IS NOT NULL;"`.
- Рекомендации **не ходят во внешние сервисы** и ничего не выдумывают:
  подключать API-ключи здесь нечего.

### Файл из раздела «Другое» не скачивается в Mini App

- **Файл больше 20 МБ.** Скачивание идёт через `getFile` публичного Bot API
  с лимитом 20 МБ — то же ограничение, что и у стриминга аудио. Решение —
  локальный Bot API server, раздел
  [15](#15-ограничение-20-мб-и-локальный-bot-api-server).
  До тех пор файл остаётся доступным в самом Telegram: кнопка
  «💬 Открыть чат с ботом» свернёт Mini App, а команда `/other` пришлёт файл
  сообщением — на отправку ботом лимит другой, 50 МБ.
- **Ничего не происходит по нажатию «Скачать».** WebView Telegram часто
  игнорирует атрибут `download` у ссылки, поэтому приложение открывает файл
  во внешнем браузере через `tg.openLink`. Если браузер заблокирован
  или ссылка не открылась — используйте кнопку перехода в чат с ботом.
- **`401` на `/other/{id}/download`** — истёк подписанный stream-токен
  (`STREAM_TOKEN_TTL`, по умолчанию 6 часов) или менялся `SECRET_KEY`.
  Обновите страницу Mini App: токены выдаются заново.
- **`404`** — у записи нет `file_id` либо файл удалён из канала-хранилища
  вручную. Карточка в базе остаётся, сам файл вернуть нельзя.
- **`502`** — Telegram не отдал файл: проверьте логи и доступность
  `api.telegram.org`.
- **Файл открывается в браузере вместо сохранения** — это `inline=true`
  (предпросмотр видео и голосовых). Кнопка «Скачать» запрашивает тот же
  адрес без `inline`, с `Content-Disposition: attachment`.

### Файлы `.db-wal` и `.db-shm`

Это журнал WAL и разделяемый индекс — нормальная часть работы SQLite.

- Удалять их **при работающем приложении нельзя**: потеряете последние
  изменения.
- `-wal` разросся до сотен мегабайт? Остановите сервис и выполните
  контрольную точку:

  ```bash
  sqlite3 data/musicbox.db "PRAGMA wal_checkpoint(TRUNCATE);"
  ```

- Копировать базу нужно через `.backup` / `VACUUM INTO`, а не `cp`
  (см. раздел [24](#24-резервное-копирование-и-восстановление-бд)).
- `database is locked` — к базе одновременно обратились два процесса
  MusicBox (например, systemd-сервис и запуск руками). Оставьте один.

### Другие частые случаи

| Симптом | Причина и решение |
|---|---|
| `ValueError: не задан BOT_TOKEN` при старте | Не заполнен `.env` или процесс запущен не из корня проекта |
| `Conflict: terminated by other getUpdates request` | Запущено два экземпляра бота с одним токеном — остановите лишний |
| `can't use getUpdates method while webhook is active` | Остался вебхук: `curl ".../deleteWebhook"` или `BOT_MODE=webhook` |
| Mini App не открывается, «страница недоступна» | Нет валидного HTTPS, неверный `WEBAPP_URL` или не выполнен `/setmenubutton` |
| Открывается белый экран Mini App | Не собран фронтенд (`npm run build`) или неверный `FRONTEND_DIST` |
| `Address already in use` | Порт 8000 занят: смените `API_PORT` или остановите другой процесс |
| Кириллица сортируется неправильно | Обновитесь: сортировка выполняется в Python (`casefold`), а не `COLLATE NOCASE` |
| Дубликаты треков | Их не должно быть: уникальность по `file_unique_id`. Один и тот же трек из разных источников имеет разные `file_unique_id` — это разные файлы для Telegram |
| Логи «съедают» диск | Задайте `LOG_FILE` (ротация) или ограничьте journald/`json-file` в Docker |
| `getMyCommands` возвращает пустой список | Команды публикуются в область видимости `all_private_chats`, а запрос без параметров читает область `default` — это разные наборы. Проверяйте так: `curl -s -G ".../getMyCommands" --data-urlencode 'scope={"type":"all_private_chats"}'` |
| Бот молчит на все сообщения | Проверьте `ALLOWED_USER_IDS`: если список задан, а вашего id в нём нет, бот игнорирует сообщения. Свой id покажет `python -m scripts.detect_channel` или @userinfobot |
| `python -m scripts.detect_channel` ничего не находит | Бот добавлен в канал участником, а не администратором, либо без права «Публикация сообщений» — скрипт пишет об этом в лог и продолжает ждать. Ещё вариант: параллельно запущен бот в режиме polling и забирает обновления себе |
| `400` при переносе папки | Папку нельзя положить внутрь самой себя или своей подпапки, перенести в другой раздел (`music` ↔ `other`) и уходить глубже 16 уровней (`MAX_FOLDER_DEPTH`) |
| Две одинаковые корневые папки | `UNIQUE` в SQLite не ловит дубли при `parent_folder_id IS NULL` (`NULL != NULL`), поэтому уникальность корневых папок проверяет репозиторий. Если дубли остались от ручной правки базы — переименуйте или перенесите треки и удалите лишнюю |
| В меню «/» меньше 31 команды | Клиент Telegram кеширует список: перезапустите приложение Telegram или выполните `python -m scripts.setup_commands` |
| В «Другом» пусто, хотя файлы отправлялись | mp3 и прочее аудио уходит в «Треки» даже когда прислано документом — так и задумано (раздел [19](#19-разделы-треки-и-другое)) |
| «Распознавание не настроено» | Штатный ответ заглушки: `RECOGNITION_PROVIDER` пуст. Это не поломка, см. раздел [9](#9-настройка-env) |

Диагностика:

```bash
curl -s http://localhost:8000/health                 # жив ли сервис
journalctl -u musicbox -n 200 --no-pager             # systemd
docker compose logs --tail=200 musicbox              # Docker
LOG_LEVEL=DEBUG python -m backend.main               # подробный лог
```

## 26. FAQ и лицензия

### FAQ

**Сколько музыки поместится?**
Практически без ограничений: файлы лежат в Telegram, на сервере — только
база с карточками треков (примерно 1 МБ на несколько тысяч треков).

**Файлы правда не хранятся у меня на диске?**
Да. При загрузке бот копирует сообщение в приватный канал и запоминает
`file_id`. Для веб-плеера файл проксируется потоком и на диск не пишется.

**Что будет, если удалить трек из канала вручную?**
Карточка останется в базе, но воспроизведение перестанет работать
(`file_id` станет невалидным). Удаляйте треки из бота или Mini App —
там есть опция удалить и файл из канала.

**Можно пользоваться вдвоём/командой?**
Да. Библиотеки пользователей полностью изолированы, хранилище-канал общее.
Чтобы ограничить круг пользователей, перечислите их ID в `ALLOWED_USER_IDS`.

**Обязательно ли настраивать Telethon?**
Нет. Без него не работает только `/tgsearch` (поиск по публичным каналам).
Пересылка аудио боту из любого канала работает всегда.

**Почему трек не попал ни в «редко», ни в «часто»?**
Между `RARE_MAX` (5) и `FREQUENT_THRESHOLD` (10) есть «серая зона»
6–9 прослушиваний. Границы настраиваются в `/settings`.

**Почему счётчик `top` в `/stats/counts` не равен 10?**
`top` — это число треков с `play_count > 0`, то есть размер выборки,
из которой берётся топ-10. Аналогично `recent` — общее число треков.

**Можно ли перенести библиотеку на другой сервер?**
Да: скопируйте `.env` и файл базы, канал и бот остаются прежними.
Убедитесь, что `SECRET_KEY` тот же (иначе просто обновятся ссылки на стрим).

**Работает ли на Windows в продакшене?**
Работает (polling + `python -m backend.main`), но для сервера
рекомендуется Linux + systemd или Docker.

**Как обновиться?**

```bash
git pull
source .venv/bin/activate && pip install -r requirements.txt
cd frontend && npm ci && npm run build && cd ..
sudo systemctl restart musicbox        # или: docker compose up -d --build
```

Миграции базы применяются автоматически при старте и идемпотентны.
**При переходе с версии 1 сначала сделайте бэкап** — раздел
[5](#5-обновление-с-версии-1-на-версию-2): миграция папок необратима.

**Можно ли откатиться с V2 на V1?**
Только восстановлением базы из бэкапа. Таблица `folders` при обновлении
пересоздаётся, обратной миграции нет.

**Почему аватарку нельзя поставить скриптом?**
В Telegram Bot API нет метода для фото профиля бота: `setMyPhoto`
не существует, `setChatPhoto` работает только для чатов. Картинку готовит
`python -m scripts.make_avatar`, ставится она вручную через @BotFather →
`/setuserpic` (раздел [7](#7-аватарка-и-профиль-бота)).
Имя и описания скрипт `setup_profile.py` ставит через API нормально.

**Работает ли распознавание исполнителя по аудио?**
Нет. `backend/services/recognition.py` — заглушка: код запросов к AudD,
ACRCloud и Genius написан, но без ключей не выполняется и на живых ключах
не проверялся.

**Почему рекомендаций меньше 15?**
Потому что база маленькая. Алгоритм не выдумывает исполнителей: он честно
добивает списки непрослушанными из вашей библиотеки и пишет недобор в
`shortfall` и `note` (раздел [21](#21-рекомендации-как-это-работает)).

**Куда делись треки после обновления?**
Никуда. Раздел «Треки» показывает только `file_type = 'audio'`, остальное —
в разделе «Другое» (раздел [19](#19-разделы-треки-и-другое)).
Вся библиотека V1 после миграции остаётся аудио.

**Почему в Mini App нет Tailwind / Material-UI?**
Приложение красится переменными темы Telegram из одного файла
`frontend/src/styles.css`, чтобы светлая и тёмная темы совпадали с клиентом
без дублирования классов (раздел
[11](#11-mini-app-страницы-сборка-разработка)).

**Где посмотреть контракт модулей?**
`docs/ARCHITECTURE.md` — контракт V1 (имена, схемы БД, маршруты, пропсы
компонентов), `docs/ARCHITECTURE-V2.md` — дополнение V2: вложенные папки,
несколько исполнителей, `file_type`, заметки, рекомендации, миграции.
